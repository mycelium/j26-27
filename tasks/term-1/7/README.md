# Подбор оптимального числа потоков

1. Узнаём число логических процессоров платформы: `Runtime.getRuntime().availableProcessors()`.
2. Для каждого размера матрицы (500, 1000, 1500) запускаем `multiplyParallel(a, b, threadsCount)`
   с разным числом потоков: 1, 2, 4, 8, 12, 16, 32. Так охватываются значения меньше, около и заметно больше числа процессоров.
3. Перед замерами делаем прогрев JIT-компилятора, затем берём медиану 5 запусков, чтобы сгладить шум.
4. Каждый результат сверяем с однопоточной версией, чтобы убедиться в корректности.
5. Считаем ускорение `T_последовательное / T_параллельное` и выбираем число потоков, после которого время
   перестаёт заметно уменьшаться. Различия в пределах погрешности измерений считаем отсутствием выигрыша
   и берём меньшее число потоков.

Ожидаемое поведение: время падает почти линейно до числа физических ядер, затем выходит на плато
(гипертрейдинг, ограничение пропускной способности памяти). При числе потоков, сильно превышающем число
процессоров, выигрыша нет, а накладные расходы на создание потоков и переключение контекста растут.
