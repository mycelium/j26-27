# 1. Java: Matrix multiplication

**Файлы:**
- `MatrixMult.java` — `multiply` (оптимизированная версия), `multiplyNaive` (базовая, для сравнения)
  и `main` (генерация матриц, замер времени обеих версий, проверка совпадения результатов).

**Запуск:**
```bash
javac MatrixMult.java
java MatrixMult 1000     # размер матрицы (по умолчанию 1000)
```

## Оптимизация

Двумерные массивы в Java хранятся построчно. В базовом алгоритме (порядок циклов `i -> j -> k`)
внутренний цикл читает `secondMatrix[k][j]` по столбцу, то есть с большим шагом по памяти,
что вызывает частые промахи кэша.

В `multiply` порядок циклов изменён на `i -> k -> j`: внутренний цикл идёт по строкам
`secondMatrix[k]` и `result[i]` последовательно, и данные хорошо ложатся в кэш.
Также `firstMatrix[i][k]` вынесен в локальную переменную `temp`.

## Методика замера

- Матрицы заполняются случайными числами с фиксированным зерном (`Random(42)`).
- Перед замером выполняется 2 прогревочных запуска (JIT-компиляция), затем 5 замеров;
  в таблице — медиана.
- Обе версии запускаются в одном процессе на одних и тех же данных;
  результаты сравниваются между собой (`results equal: true`).


## Результаты

С ростом размера матрицы выигрыш растёт: матрица перестаёт помещаться в кэш,
и столбцовый доступ в базовой версии становится значительно дороже.
Абсолютные значения зависят от процессора; ускорение — от 7x и выше.
