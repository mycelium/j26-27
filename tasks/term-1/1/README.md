# Лабораторная работа № 1. Умножение матриц

## Задание

- Реализовать метод `public static double[][] multiply(double[][] firstMatrix, double[][] secondMatrix)`
- Измерить время умножения матриц большой размерности
- Оптимизировать алгоритм и описать применённые подходы

## Реализация

В программе сравниваются три способа умножения матриц. Все способы имеют асимптотическую сложность `O(n³)`, но по-разному обращаются к памяти.

### Классический алгоритм

Метод `multiplyClassic` использует порядок циклов `i-j-k`. Для каждого элемента результата вычисляется скалярное произведение строки первой матрицы и столбца второй матрицы.

Во внутреннем цикле происходит обращение к элементам `secondMatrix[k][j]`. В Java двумерный массив является массивом отдельных строк, поэтому элементы одного столбца не расположены в памяти последовательно. Из-за этого процессор хуже использует кэш.

### Транспонирование второй матрицы

Метод `multiplyTransposed` сначала транспонирует вторую матрицу. После этого скалярное произведение вычисляется между двумя строками, элементы которых расположены последовательно.

Такой подход позволяет процессору читать элементы матрицы подряд и реже обращаться к более медленной оперативной памяти. При этом требуется дополнительная память для транспонированной матрицы. Время транспонирования включается в итоговый замер.

### Изменение порядка циклов

Метод `multiplyOptimized` использует порядок циклов `i-k-j`. Во внутреннем цикле последовательно обходятся строка второй матрицы и строка результата:

```java
for (int i = 0; i < firstMatrix.length; i++) {
    double[] firstRow = firstMatrix[i];
    double[] resultRow = result[i];
    for (int k = 0; k < firstColumns; k++) {
        double firstValue = firstRow[k];
        double[] secondRow = secondMatrix[k];
        for (int j = 0; j < secondColumns; j++) {
            resultRow[j] += firstValue * secondRow[j];
        }
    }
}
```

Последовательный доступ к данным лучше использует кэш процессора и позволяет JIT-компилятору эффективнее оптимизировать внутренний цикл. Дополнительная матрица при этом не требуется. Именно эта реализация вызывается из требуемого заданием метода `multiply`.

## Методика измерения

- Для всех методов используются одинаковые матрицы, созданные с фиксированным начальным значением генератора случайных чисел
- Перед измерением каждый метод пять раз запускается на матрицах `128 × 128`, чтобы JIT-компилятор успел оптимизировать часто выполняемый код
- Каждый метод измеряется пять раз с помощью `System.nanoTime()`
- В качестве результата используется медианное время, менее чувствительное к единичным выбросам
- Перед измерением результаты всех реализаций проверяются на заранее известном примере

Необходимость прогрева при измерении производительности JVM описана в рекомендациях [OpenJDK по микробенчмаркам](https://wiki.openjdk.org/display/HotSpot/MicroBenchmarks).

## Результаты

Характеристики системы:

- MacBook Air, Apple M3
- 16 ГБ оперативной памяти
- Oracle JDK 21.0.10 LTS
- Размер матриц: `1000 × 1000`
- Количество измеряемых запусков: 5

| Метод | Медианное время, мс | Ускорение |
|---|---:|---:|
| Классический `i-j-k` | 860,628 | 1,00× |
| С транспонированием | 652,401 | 1,32× |
| Оптимизированный `i-k-j` | 165,440 | 5,20× |

Наибольшее ускорение дал порядок циклов `i-k-j`: на матрицах `1000 × 1000` он оказался примерно в 5,2 раза быстрее классической реализации.
