# Задание 1. Умножение матриц на Java

## Задача

1. Написать функцию `multiply`, которая перемножает две матрицы.
2. Замерить, сколько времени занимает умножение больших матриц.
3. Ускорить умножение и описать, что для этого сделано.

## Как запустить

```bash
javac MatrixMult.java
java MatrixMult
```

Сначала программа проверяет все версии на маленьком примере (2×3 на 3×2, правильный ответ `[22, 28], [49, 64]`). Потом умножает случайные матрицы размером 200, 500 и 1000 и выводит время каждой версии и ускорение по сравнению с обычной.

## Что есть в программе

| Метод | Что делает |
|---|---|
| `multiply` | Обычное умножение «по формуле», циклы в порядке i-j-k |
| `multiplyReordered` | Те же циклы, но в порядке i-k-j |
| `multiplyOptimized` | Порядок i-k-j + повторяющиеся значения вынесены из внутреннего цикла |

Вспомогательные методы:
- `randomMatrix` — создаёт матрицу со случайными числами;
- `printMatrix` — печатает матрицу;
- `measureMs` — замеряет время одной версии умножения.

Если матрицы нельзя перемножить (число столбцов первой не равно числу строк второй), все версии бросают `IllegalArgumentException`.

## Как замерялось время

- Время считается через `System.nanoTime()` и переводится в миллисекунды.
- Все версии умножают одни и те же матрицы.

## Результаты

Время в миллисекундах:

| Размер | multiply | multiplyReordered | multiplyOptimized |
|---|---|---|---|
| 200 | 13.64 | 14.53 | 13.15 |
| 500 | 147.22 | 72.39 | 85.99 |
| 1000 | 1737.50 | 613.99 | 232.24 |

На матрицах 1000×1000:
- `multiplyReordered` быстрее обычной версии в **2.8 раза**;
- `multiplyOptimized` быстрее в **7.5 раза**.


## Почему обычная версия медленная

Матрица в Java (`double[][]`) — это набор отдельных строк. Числа одной строки лежат в памяти рядом, а разные строки могут лежать далеко друг от друга.

Процессор читает память не по одному числу, а сразу кусками и держит их в быстрой памяти — **кэше**. Если идти по строке подряд, нужные числа уже оказываются в кэше. Если прыгать между строками, каждый раз приходится заново ждать данные из медленной оперативной памяти.

В обычной версии самый внутренний цикл идёт **по столбцу** второй матрицы: `secondMatrix[k][j]` при каждом шаге берётся из новой строки. Поэтому процессор постоянно ждёт память.

Это видно по цифрам: размер вырос с 500 до 1000 в 2 раза, количество операций — в 8 раз, а время — почти в 12 раз. Матрица 1000×1000 занимает около 8 МБ и уже не помещается в кэш.

На размере 200 все версии работают примерно одинаково: такая матрица и так целиком помещается в кэш.

## Оптимизация 1: другой порядок циклов (`multiplyReordered`)

Поменяли местами два внутренних цикла: было i-j-k, стало i-k-j. Формула та же, ответ тот же. Но теперь самый внутренний цикл идёт по `j`, то есть **по строке**. Числа читаются подряд, и кэш работает хорошо.

Результат: примерно в 3 раза быстрее.

## Оптимизация 2: вынос лишнего из цикла (`multiplyOptimized`)

Во внутреннем цикле некоторые значения не меняются, но раньше вычислялись заново на каждом шаге. Теперь они берутся один раз перед циклом:

```java
for (int i = 0; i < firstRows; i++) {
    double[] resultRow = result[i];                 // строка результата
    for (int k = 0; k < commonSize; k++) {
        double firstElement = firstMatrix[i][k];    // одно число, не меняется по j
        double[] secondRow = secondMatrix[k];       // строка второй матрицы
        for (int j = 0; j < secondCols; j++) {
            resultRow[j] += firstElement * secondRow[j];
        }
    }
}
```

Теперь внутренний цикл: умножить число на элемент строки и прибавить к элементу другой строки.

Результат: ещё примерно в 2.5 раза быстрее, всего в 7.5 раза быстрее обычной версии.

## Вывод

Скорость умножения матриц больше всего зависит не от количества операций, а от того, **в каком порядке** читается память. Не меняя сам алгоритм, только порядком циклов и упрощением внутреннего цикла удалось ускорить умножение в 7.5 раза.
