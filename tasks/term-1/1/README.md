# 1. Java: Matrix multiplication. Постановка задачи.

* реализовать функцию `public static double[][] multiply(double[][] firstMatrix, double[][] secondMatrix);`
* Вывести время выполнения для матриц большой размерности
* Оптимизировать время выполнения (описать в README применённые подходы)

## Функции

* `multiply(firstMatrix, secondMatrix)` -- оптимизированное умножение матриц: обход циклов i-k-j и параллельная обработка строк результата.
* `multiplyNaive(firstMatrix, secondMatrix)` -- базовое умножение матриц с обходом циклов i-j-k. Результат этой функции считается эталонным.
* `randomMatrix(rows, cols)` -- создание матрицы заданного размера, заполненной случайными числами в диапазоне от 0 до 1.
* `main(args)` -- генерирует две квадратные матрицы, трижды запускает обе версии умножения, выводит время выполнения каждой и проверяет, что результаты совпадают.

## Запуск

```
java MatrixMult.java          # матрицы 1000x1000 (по умолчанию)
java MatrixMult.java 2000     # матрицы 2000x2000
```

## Размерность матриц в тестах

В тестах перемножаются две квадратные матрицы размера **1000 × 1000** (≈ 10⁹ операций умножения-сложения). Размер можно изменить аргументом командной строки. Каждая версия запускается 3 раза на одних и тех же матрицах.

## Описание оптимизации

Изначально умножение реализовано тремя вложенными циклами в порядке i-j-k (функция `multiplyNaive`). В `multiply` применены два приёма.

## Описание оптимизации

Базовая версия (`multiplyNaive`) использует порядок циклов i-j-k. В `multiply` применены два приёма.

**1. Порядок циклов i-k-j.** Процессор подгружает в кэш целый блок соседних адресов, а матрица в Java хранится построчно. При обходе i-j-k внутренний цикл идёт по столбцу второй матрицы, её элементы лежат в памяти не подряд, и кэш используется плохо. При обходе i-k-j внутренний цикл идёт по строкам обеих матриц, обращения к памяти последовательные, и кэш работает эффективно. Результат при этом не меняется: порядок суммирования по `k` сохраняется.

**2. Параллельная обработка строк.** Строки результата независимы друг от друга, поэтому они распределяются по потокам через `IntStream.range(0, rows).parallel()`, синхроонизация не требуется.
