# MatrixMult

## Описание алгоритмов

* **Стандартное умножение (`multiply`)** - классический алгоритм с тремя вложенными циклами в порядке `i -> j -> k`.
* **Оптимизированное умножение (`multiplyCyclePermutation`)** - алгоритм с измененным порядком циклов `i -> k -> j`.

---

## Результаты замеров работы алгоритмов

Замеры проводились на случайных матрицах размерностью **1000 × 1000** элементов запуском алгоритмов 10 раз.

|          Алгоритм          | Среднее время выполнения |
|:--------------------------:|:------------------------:|
|         `multiply`         |          1168ms          |
| `multiplyCyclePermutation` |          175ms           |

## Примененные подходы к оптимизации умножения

### Проблема базового алгоритма (`i -> j -> k`)

В стандартном алгоритме самый внутренний цикл идет по индексу `k`:

```java
resultMatrix[i][j]+=firstMatrix[i][k]*secondMatrix[k][j];
```

Перебор элементов матрицы `secondMatrix[k][j]` происходит по столбцам. В Java двухмерные массивы хранятся как массив
массивов. Элементы одной строки лежат в памяти последовательно, а элементы одного столбца не последовательно. Из-за
этого на каждой итерации внутреннего цикла происходят постоянные промахи кэша процессора. Процессору приходится
постоянно подгружать новые не кэшированные данные из оперативной памяти.

### Решение в оптимизированном алгоритме (`i -> k -> j`)

```java
double tempVal = firstMatrix[i][k];
for(
int j = 0;
j<secondMatrix[0].length;j++){
resultMatrix[i][j]+=tempVal *secondMatrix[k][j];
		}
```

Теперь во внутреннем цикле индекс `j` меняется последовательно. Чтение строки `secondMatrix[k]` и запись в строку
`resultMatrix[i]` строго слева направо. Элементы строк полностью попадают в кэш-линию процессора. Процессор считывает
блок памяти один раз и обрабатывает последующие элементы из кэша. Вынесение значения `firstMatrix[i][k]` в переменную
`tempVal` перед внутренним циклом избавляет программу от лишних обращений к памяти первой матрицы внутри цикла по `j`.
