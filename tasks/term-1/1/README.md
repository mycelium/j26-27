# Лабораторная работа 1. Умножение матриц

## Постановка задачи

- Реализовать функцию `public static double[][] multiply(double[][] firstMatrix, double[][] secondMatrix);`
- Вывести время выполнения для матриц большой размерности.
- Оптимизировать время выполнения и описать применённые подходы.

## Реализация

В `MatrixMult.java` реализованы два метода для сравнения: `multiplyBasic` и
`multiplyOptimized`. Оба принимают матрицы размером `m × n` и `n × p` и возвращают
новую матрицу размером `m × p`. Исходные матрицы не изменяются.

### Базовый метод — multiplyBasic

Используются три вложенных цикла в порядке `i → j → k`. Для каждого элемента
результата вычисляется сумма произведений элементов строки первой матрицы
и столбца второй:

```text
result[i][j] += firstMatrix[i][k] * secondMatrix[k][j]
```

Во внутреннем цикле меняется `k`, поэтому при чтении `secondMatrix[k][j]`
приходится постоянно переходить между строками второй матрицы.

### Оптимизированный метод — multiplyOptimized

Формула вычисления остаётся той же, но порядок циклов изменён на `i → k → j`.
Теперь во внутреннем цикле перебираются элементы одной строки второй матрицы
и одной строки результата.

В Java `double[][]` — это массив ссылок на отдельные массивы строк.
Последовательный обход элементов строки лучше использует кеш процессора,
чем переходы между строками при обходе столбца.

Также перед внутренним циклом в локальные переменные сохраняются:

- строки первой матрицы и результата: `firstRow` и `resultRow`;
- строка второй матрицы: `secondRow`;
- элемент первой матрицы: `value`.

Это сокращает повторные обращения по индексам во внутреннем цикле.
Измерения сравнивают обе реализации целиком и не выделяют вклад каждой
оптимизации отдельно.

Оба метода однопоточные. Их вычислительная сложность — `O(m · n · p)`,
для квадратных матриц — `O(n³)`. Оптимизация не меняет сложность алгоритма,
а уменьшает фактическое время выполнения за счёт порядка доступа к данным.
Для результата выделяется `O(m · p)` памяти.

Перед вычислениями `checkDimensions` и `checkMatrix` проверяют совместимость
размеров, отсутствие пустых матриц и `null`, а также одинаковую длину строк.
При некорректных данных выбрасывается `IllegalArgumentException`.

## Измерение времени

В `main` создаются случайные квадратные матрицы размером 250×250, 500×500
и 1000×1000. Используется `Random(42)`, чтобы при повторном запуске получать
те же входные данные. Оба метода умножают одни и те же матрицы.

Перед измерениями каждый метод вызывается 10 раз на матрицах 200×200
для прогрева JVM. Затем для каждого размера выполняется по пять измерений
каждого метода. Порядок запуска методов чередуется. В таблицу выводится
медиана — среднее по позиции значение из пяти отсортированных времён.

Время измеряется через `System.nanoTime()`. В него входят проверка входных
данных, выделение массива результата и само умножение. Генерация матриц
и вывод в консоль выполняются вне измеряемого участка. После измерения
один элемент результата сохраняется в поле `volatile lastResult`, чтобы
вычисленный результат использовался программой.

## Результаты

Запуск выполнен 20 октября 2026 года на macOS 26.6.2, архитектура arm64,
OpenJDK 25.0.2 (Temurin). Время указано в миллисекундах.

| Размер каждой матрицы | multiplyBasic, мс | multiplyOptimized, мс | Ускорение |
| --- | ---: | ---: | ---: |
| 250×250 | 12,472 | 2,553 | 4,89 раза |
| 500×500 | 104,620 | 19,068 | 5,49 раза |
| 1000×1000 | 1042,745 | 157,035 | 6,64 раза |

Ускорение рассчитано как отношение медианного времени базового метода
к медианному времени оптимизированного. В этом запуске изменение порядка
обхода и сохранение значений в локальные переменные сократили время
умножения для всех трёх размеров. На матрицах 1000×1000 время уменьшилось
примерно с 1,04 секунды до 0,16 секунды.

При повторном запуске значения могут отличаться из-за нагрузки на компьютер,
работы JIT-компилятора и сборщика мусора. Эти измерения показывают скорость
выполнения; отдельной проверки правильности результата в `main` нет.
