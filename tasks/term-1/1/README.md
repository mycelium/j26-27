## Применённые оптимизации

### 1. Классический алгоритм (базовый)

Тройной цикл `i → j → k`:

```
C[i][j] += A[i][k] * B[k][j]
```

Минусы:

- Плохая локальность данных: `B` читается по столбцам → много cache miss’ов
- Нет параллелизма

### 2. Транспонирование второй матрицы + блокирование (tiling)

**Транспонирование `B` → `Bt`**

После транспонирования внутренний цикл идёт по строке `Bt[j]`, то есть по последовательным адресам в памяти. Это резко снижает количество промахов кэша.

**Блочное умножение**

Матрицы разбиваются на блоки размера `BLOCK_SIZE × BLOCK_SIZE` (по умолчанию 64).  
Внутренние циклы работают с блоками, которые помещаются в L1/L2 кэш.  
Это уменьшает количество обращений к основной памяти.

Порядок обхода блоков: `i0 → j0 → k0`, внутри блока — классический `i-j-k` по уже транспонированной матрице.

## Результаты

Size     | Simple (ms)    | Blocked (ms)   | Speedup   
---------+----------------+----------------+----------------
256      | 15,01          | 4,65           | 3,23x
512      | 115,63         | 35,63          | 3,25x
1024     | 2124,47        | 294,28         | 7,22x
1536     | 20446,23       | 1054,70        | 19,39x

## Вывод

Оптимизация с транспонированием второй матрицы и делением на блоки даёт существенное ускорение на больших матрицах.  
На матрице 1536×1536 ускорение составило примерно **19×** относительно классического тройного цикла.

Причина — значительное улучшение локальности данных:
- после транспонирования `B` все обращения идут по последовательным адресам;
- блоки 64×64 хорошо помещаются в кэш процессора.

Сложность алгоритма при этом остаётся O(n³).
