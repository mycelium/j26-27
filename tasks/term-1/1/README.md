# Лабораторная работа 1. Java: Matrix multiplication

Рузанова Анастасия, группа 40102

## Задание

* реализовать функцию `public static double[][] multiply(double[][] firstMatrix, double[][] secondMatrix);`
* вывести время выполнения для матриц большой размерности
* оптимизировать время выполнения

## Запуск

```bash
javac MatrixMult.java
java MatrixMult
```

Программа генерирует случайные квадратные матрицы 500×500, 1000×1000 и 2000×2000,
умножает их наивным и оптимизированным способом, выводит время и проверяет, что результаты совпадают.

## Реализация

`multiply` проверяет входные данные (`null`, пустые матрицы, несовпадение размеров —
бросается `IllegalArgumentException`) и возвращает матрицу `n×p` для входных `n×m` и `m×p`.

Для сравнения в классе оставлена наивная версия `multiplyNaive` (порядок циклов i-j-k).

## Применённые оптимизации

1. **Порядок циклов i-k-j вместо i-j-k.**
   В наивной версии внутренний цикл идёт по `secondMatrix[k][j]` с изменением `k`, то есть
   прыгает по разным строкам (столбцовый доступ) — почти каждое обращение даёт промах кэша.
   При порядке i-k-j внутренний цикл последовательно проходит по строке `secondMatrix[k]`
   и строке результата, память читается подряд, работает аппаратный prefetch,
   а JIT может векторизовать цикл (SIMD).

2. **Вынос ссылок на строки и элемента `a[i][k]` из внутреннего цикла.**
   `aRow`, `resultRow`, `bRow` и `aik` сохраняются в локальные переменные — во внутреннем
   цикле нет повторного разыменования двумерного массива и лишних проверок границ.

3. **Пропуск нулевых элементов.** Если `a[i][k] == 0`, вся строка вклада пропускается
   (полезно для разреженных матриц, на плотных почти ничего не стоит).

4. **Блочное умножение (tiling).** Циклы по `k` и `j` разбиты на блоки размером `BLOCK = 64`.
   Блок `secondMatrix` размером 64×64 double (32 КБ) помещается в кэш процессора и
   переиспользуется для всех строк `i`, а не вытесняется из кэша на больших матрицах.
   Размер блока подобран экспериментально (пробовались 32, 64, 96, 128, 256, 512).

5. **Прогрев JIT** перед замерами, чтобы время не включало интерпретацию и компиляцию.

## Результаты

Java 27, Windows 10, один поток:

| Размер      | Наивный (i-j-k) | i-k-j    | i-k-j + блоки |
|-------------|-----------------|----------|---------------|
| 500×500     | ~250 мс         | ~120 мс  | ~80 мс        |
| 1000×1000   | ~7 000 мс       | ~1 150 мс | ~460 мс      |
| 2000×2000   | ~110 000 мс     | ~9 700 мс | ~3 900 мс    |

На матрице 2000×2000 оптимизированная версия быстрее наивной примерно в 25–50 раз
(время заметно колеблется от запуска к запуску). Сложность алгоритма осталась O(n³) —
ускорение получено только за счёт эффективной работы с памятью.
