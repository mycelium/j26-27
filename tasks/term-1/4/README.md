# Word Frequency Counter

Подсчёт частоты слов в текстовом файле в двух вариантах:

- **memory**: файл целиком загружается в память (`Files.readString`), затем обрабатывается;
- **stream**: файл читается построчно (`BufferedReader`), в памяти хранятся только текущая строка и карта счётчиков. Подходит для файлов больше оперативной памяти.

## Запуск

```bash
javac WordFrequencyCounter.java
java WordFrequencyCounter <файл> [memory|stream|compare] [N]
```

- `<файл>`: путь к текстовому файлу в кодировке UTF-8;
- режим по умолчанию: `stream`;
- `compare`: запускает оба варианта и проверяет, что результаты совпадают (только для файлов, которые помещаются в память);
- `N`: сколько самых частых слов вывести (по умолчанию 25).

Примеры:

```bash
java WordFrequencyCounter text.txt
java WordFrequencyCounter text.txt memory 10
java WordFrequencyCounter text.txt compare
```

Вывод: общее число слов, число уникальных слов и топ-N слов по убыванию частоты (при равной частоте по алфавиту).

## Правила подсчёта

- Слово это последовательность букв (любой алфавит), дефисов и апострофов.
- Регистр не учитывается: `Java` и `java` считаются одним словом.
- Всё остальное (пробелы, знаки препинания, цифры) разделяет слова.

## Как получить большой файл для проверки

Большой файл собирается из многократно повторённого `text.txt`:

```bash
for i in $(seq 1 270000); do cat text.txt; done > big2.txt
ls -lh big2.txt
```

Размер результата примерно 1.1 ГБ. Файл не хранится в репозитории.

## Результаты эксперимента

Файл `big2.txt`, 1.1 ГБ, 78 064 000 слов, из них 210 уникальных.

| Режим | Условия | Результат |
|-------|---------|-----------|
| memory | размер кучи по умолчанию: `1910 МБ` | `OutOfMemoryError: Java heap space` в `Files.readString` |
| stream | `-Xmx64m` | отработал, время: `41.821s` |

```bash
java WordFrequencyCounter big2.txt memory 21           # падает с OutOfMemoryError
time java -Xmx64m WordFrequencyCounter big2.txt stream 21   # работает при куче 64 МБ
```

Потоковый вариант справился с файлом в 1.1 ГБ при куче всего 64 МБ, то есть потребление памяти не зависит от размера файла. Оно зависит только от числа **разных** слов.

Конфигурация машины: ОЗУ `7.5 ГБ`, процессор ` AMD Ryzen 5 7430U with Radeon Graphics`, Java `openjdk 21.0.12.1 2026-08-18`, Ubuntu в WSL2.

## Ограничения

- Если в файле нет переносов строк (вся информация в одной строке), `readLine()` загрузит её целиком, и преимущество потокового варианта пропадает. Решение: читать блоками через `Reader.read(char[])` и склеивать слова на границах блоков (не реализовано).
- Если уникальных слов очень много (десятки миллионов), карта счётчиков тоже перестанет помещаться в память.
- Файл в кодировке, отличной от UTF-8, приведёт к `MalformedInputException` или к искажённым словам.
