## 4. Java: Word Frequency Counter

Программа считает, сколько раз каждое слово встречается в текстовом файле, и выводит результат. Подсчёт сделан двумя способами: с загрузкой всего файла в память и с потоковой обработкой.

### Запуск

```bash
javac WordFrequencyCounter.java
java WordFrequencyCounter full input.txt     # вариант 1: весь файл в память
java WordFrequencyCounter stream input.txt   # вариант 2: потоковая обработка
```

`input.txt` — небольшой файл для проверки. В нём только буквы английского алфавита, разделённые пробелами, и каждая буква считается отдельным словом. Первая строка содержит весь алфавит, следующие строки всё короче, поэтому буквы из начала алфавита встречаются чаще, и результат легко проверить вручную.

### Что считается словом

Слово — это подряд идущие буквы или цифры (русские и английские). Всё остальное (пробелы, знаки препинания, кавычки, дефисы) разделяет слова. Регистр не учитывается: «Кот» и «кот» считаются одним словом.

### Вариант 1. Загрузка всего файла — `countWords`

1. `Files.readString` читает весь файл в одну строку.
2. Строка делится на слова методом `split`.
3. Каждое слово добавляется в словарь `HashMap`, где ключ — слово, а значение — сколько раз оно встретилось.

Это просто, но весь текст целиком лежит в оперативной памяти. Если файл больше доступной памяти, программа падает с ошибкой `OutOfMemoryError`.

### Вариант 2. Потоковая обработка — `countWordsStreaming`

1. Файл открывается через `BufferedReader`, который читает его небольшими порциями.
2. Символы читаются по одному. Пока идут буквы или цифры, они добавляются к текущему слову в `StringBuilder`.
3. Как только встречается другой символ, слово закончилось: оно добавляется в словарь, а `StringBuilder` очищается.

В памяти одновременно находятся только текущее слово и словарь, а не весь файл. Поэтому так можно обработать файл любого размера.

Файл открыт в `try (...)`: он автоматически закроется после чтения, даже если произойдёт ошибка.

### Вывод результата — `printFrequencies`

Печатается общее количество слов, количество разных слов и 20 самых частых слов. Слова отсортированы по убыванию частоты, а при одинаковой частоте — по алфавиту. Печатаются не все слова, потому что в большом файле их может быть очень много.

### Результат на input.txt

Оба варианта выдают одно и то же:

```
Всего слов: 49
Разных слов: 26
Самые частые слова:
  a: 5
  b: 4
  c: 4
  d: 3
  e: 3
  f: 3
  g: 2
  ...
  m: 2
  n: 1
  ...
```

Это совпадает с ожидаемым: `a` есть во всех 5 строках, `b` и `c` в 4 строках, `d`–`f` в 3, `g`–`m` в 2, а `n`–`z` только в первой строке.

### Проверка на большом файле

Чтобы проверить работу с файлом больше доступной памяти, можно создать большой файл и ограничить память Java до 64 МБ параметром `-Xmx64m`:

```bash
yes "The quick brown fox jumps over the lazy dog" | head -n 5000000 > big.txt
java -Xmx64m WordFrequencyCounter full big.txt
java -Xmx64m WordFrequencyCounter stream big.txt
```

Файл получается размером около 210 МБ, то есть больше, чем 64 МБ памяти.

- **full** падает с ошибкой `java.lang.OutOfMemoryError: Java heap space`: файл не помещается в память.
- **stream** успешно считает все 45 000 000 слов.

Это показывает, что потоковый вариант работает с файлами, которые больше доступной памяти.

### Ограничение

В потоковом варианте память всё равно нужна для словаря. Его размер зависит не от размера файла, а от количества **разных** слов. В обычных текстах разных слов немного (десятки или сотни тысяч), поэтому словарь легко помещается в память.
